📋 Полезные команды для управления

bash

# Просмотр логов в реальном времени

docker-compose logs -f


# Просмотр статуса контейнера

docker-compose ps


# Остановка BitPlay

docker-compose down


# Запуск после остановки

docker-compose up -d


# Перезапуск

docker-compose restart


# Вход в контейнер (для отладки)

docker exec -it bitplay /bin/sh

⚙️ Настройка BitPlay

  1. Откройте веб-интерфейс: http://localhost:3347
  2. Перейдите в раздел Settings (Настройки)
  3. Настройте:
  • Proxy SOCKS5 (если нужен)
  • Prowlarr или Jackett для поиска торрентов
  • Основная аутентификация (для защиты)

🔒 Настройка авторизации (рекомендуется)

Остановите контейнер и добавьте переменные окружения:

bash

# Останавливаем

docker-compose down


# Редактируем docker-compose.yml

nano docker-compose.yml

Добавьте секцию environment:

yaml

version: '3.8'


services:

bitplay:

image: ghcr.io/aculix/bitplay:latest

container_name: bitplay

ports:

- 3347:3347

environment:

- BITPLAY_AUTH_USERNAME=admin

- BITPLAY_AUTH_PASSWORD=ваш_безопасный_пароль

- BITPLAY_MAX_REMUX=3

volumes:

- ./config:/app/config

- ./torrent-data:/app/torrent-data

restart: unless-stopped

Запустите снова:

bash

docker-compose up -d

📁 Структура данных

  • ./config/ - содержит settings.json с настройками BitPlay
  • ./torrent-data/ - временные файлы торрентов (очищаются при перезапуске)

🧹 Очистка кэша

Через веб-интерфейс: Settings → Maintenance → Clear Cache

Или вручную:

bash

docker exec -it bitplay rm -rf /app/torrent-data/*

❓ Часто задаваемые вопросы

Не открывается веб-интерфейс?

bash

# Проверьте, что контейнер запущен

docker-compose ps


# Проверьте порт

sudo netstat -tlnp | grep 3347


# Проверьте логи

docker-compose logs

Нужно изменить порт?

В файле docker-compose.yml измените:

yaml

ports:

- 8080:3347 # теперь доступно на порту 8080

Проблемы с сетью?

Проверьте файрвол:

bash

sudo ufw allow 3347/tcp

# или

sudo iptables -A INPUT -p tcp --dport 3347 -j ACCEPT

Контейнер работает, но есть проблема с docker-compose

Контейнер запущен и работает (порт 3347 слушается), но проблема в том, что вы ввели docker-compose не в той директории. Давайте это исправим.

Шаг 1: Перейдите в правильную директорию

bash

# Переходим в директорию с docker-compose.yml
cd ~/bitplay

# Проверяем, что файл существует
ls -la docker-compose.yml

Шаг 2: Проверьте статус контейнера через docker-compose

bash

cd ~/bitplay
docker-compose ps
docker-compose logs --tail=20

Шаг 3: Проверьте работу через curl

bash

# Проверяем, что сервер отвечает
curl -v http://localhost:3347

# Или через IP 127.0.0.1
curl -v http://127.0.0.1:3347

Шаг 4: Проверка изнутри контейнера

bash

# Проверяем, что внутри контейнера сервер работает
docker exec -it bitplay curl -s http://localhost:3347 | head -20

# Или просто проверяем, что сервер отвечает
docker exec -it bitplay wget -qO- http://localhost:3347 | head -20

Шаг 5: Перезапуск контейнера (если нужно)

bash

cd ~/bitplay

# Перезапускаем
docker-compose restart

# Смотрим логи
docker-compose logs -f

Шаг 6: Проверка в браузере

Попробуйте открыть в Firefox:

  1. http://127.0.0.1:3347 (вместо localhost)
  2. http://[::1]:3347 (IPv6 localhost)
  3. http://ваш-IP-адрес:3347 (узнайте через hostname -I)

Возможная проблема: Firefox использует прокси

Проверьте настройки Firefox:

  1. Откройте Firefox
  2. Настройки → Общие → Настройки сети
  3. Выберите "Без прокси" или добавьте localhost, 127.0.0.1 в исключения

Возможная проблема: Неправильный порт

bash

# Проверяем, какой порт слушается
sudo netstat -tlnp | grep 3347

# Проверяем, что контейнер слушает на всех интерфейсах
docker port bitplay
# Должно показать: 3347/tcp -> 0.0.0.0:3347

Полное решение: перезапуск с проверкой

bash

cd ~/bitplay

# Остановка контейнера
docker-compose down

# Проверка, что порт освободился
sudo netstat -tlnp | grep 3347

# Запуск снова
docker-compose up -d

# Ожидание запуска (несколько секунд)
sleep 3

# Проверка логов
docker-compose logs --tail=30

# Проверка через curl
curl http://localhost:3347

Альтернативный способ: использовать IP хоста

bash

# Узнаем IP-адрес
ip -4 addr show | grep inet | grep -v 127.0.0.1

# Или
hostname -I

# Попробуйте открыть в браузере:
# http://<IP-адрес>:3347

Проверка, что контейнер действительно отвечает

bash

# Прямой запрос к контейнеру
docker exec bitplay curl -s -o /dev/null -w "%{http_code}" http://localhost:3347
# Должно вернуть 200 или 302

# Запрос к хосту
curl -s -o /dev/null -w "%{http_code}" http://localhost:3347

Если ничего не помогает - проверка логов ошибок

bash

cd ~/bitplay
docker-compose logs | grep -i error
docker-compose logs | grep -i fail
docker-compose logs --tail=50
