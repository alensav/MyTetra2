Вот структурированная рабочая инструкция для ежедневного использования настроенной системы создания аудиокниг на Astra Linux.

Инструкция составлена с учетом вашего уровня технической подготовки и текущего состояния системы.


📖 Рабочая инструкция: Генерация аудиокниг (Astra Linux + Docker + Piper)

1. Что уже готово и работает

  • ✅ Собран Docker-образ audiobook-maker на базе Ubuntu 24.04 (решает проблемы с устаревшей glibc и версиями Go/Calibre).
  • ✅ Скачана и настроена русская TTS-модель: ru_RU-ruslan-medium.onnx (находится в ~/.config/QuickPiperAudiobook/).
  • ✅ Установлены утилиты для предобработки текстов: pandoc и poppler-utils.


2. Основной рабочий процесс (2 шага)

Шаг 1: Подготовка исходного файла (конвертация в .txt)

Движок Piper лучше всего работает с чистым текстом. Если ваша книга в формате EPUB, FB2, DOCX или PDF, предварительно конвертируйте её.

Для EPUB, FB2 или DOCX:

bash

pandoc исходная_книга.epub -t plain -o книга.txt

Для PDF:

bash

pdftotext исходная_книга.pdf книга.txt

(Если у вас уже есть файл .txt, этот шаг пропускается).

Шаг 2: Генерация MP3-файла через Docker

Выполните команду, указав имя вашего текстового файла. Флаги --mp3 и --speak-utf-8 гарантируют корректную работу с кириллицей и создание удобного формата.

bash

docker run --rm \

-v ~/:/books \

-v ~/.config/QuickPiperAudiobook:/root/.config/QuickPiperAudiobook \

audiobook-maker \

--mp3 --speak-utf-8 --threads=1 \

--model=ru_RU-ruslan-medium.onnx книга.txt

Важно: Консоль не будет выводить прогресс-бар. Это нормальное поведение. Процесс может занять от нескольких минут до часа (для больших книг). Вы можете контролировать загрузку CPU через glances или htop во втором окне терминала.


3. Рекомендуемая автоматизация (Bash-функция)

Чтобы не вводить длинную команду Docker каждый раз, добавьте специальную функцию в ваш профиль.

1. Добавьте функцию в ~/.bashrc:

bash

cat >> ~/.bashrc << 'EOF'


# Функция для быстрой конвертации книг в аудиокниги

make-audiobook() {

if [ -z "$1" ]; then

echo "Использование: make-audiobook <файл.txt>"

return 1

fi

local abs_path=$(realpath "$1")

local dir=$(dirname "$abs_path")

local file=$(basename "$abs_path")

echo "🎧 Запуск генерации: $file"

docker run --rm \

-v "$dir":/books \

-v ~/.config/QuickPiperAudiobook:/root/.config/QuickPiperAudiobook \

audiobook-maker \

--mp3 --speak-utf-8 --threads=1 \

--model=ru_RU-ruslan-medium.onnx "$file"

echo "✅ Готово! Файл сохранен в: $dir/${file%.txt}.mp3"

}

EOF

2. Примените изменения:

bash

source ~/.bashrc

3. Использование: Теперь, находясь в любой папке, достаточно ввести:

bash

make-audiobook книга.txt


4. Настройка по умолчанию (Опционально)

Чтобы не передавать флаги --mp3, --speak-utf-8 и --model каждый раз, создайте файл конфигурации. Программа будет читать его автоматически.

bash

mkdir -p ~/.config/QuickPiperAudiobook

cat > ~/.config/QuickPiperAudiobook/config.yaml << 'EOF'

output: "."

model: "ru_RU-ruslan-medium.onnx"

mp3: true

chapters: false

speak-utf-8: true

threads: 1

EOF

После этого команду можно будет сократить до:

bash

make-audiobook книга.txt

# или вручную:

docker run --rm -v ~/:/books -v ~/.config/QuickPiperAudiobook:/root/.config/QuickPiperAudiobook audiobook-maker книга.txt

5. Возможные альтернативные голоса

Если голос ruslan (мужской, средний) вам не подойдет, вы можете скачать другие русские модели из репозитория rhasspy/piper-voices и положить их в ту же папку ~/.config/QuickPiperAudiobook/.

Доступные варианты (нужны оба файла: .onnx и .onnx.json):

  • ru_RU-irina-medium (женский голос, хорошее качество)
  • ru_RU-denis-medium (мужской голос, альтернативный тембр)
  • ru_RU-dmitri-medium (мужской голос)

Для смены голоса просто измените имя модели в config.yaml или в команде запуска.


6. Устранение типовых "псевдо-ошибок"

  1. ERRO failed sending alert notification... exec: "notify-send": executable file not found
    • Статус: Игнорировать. Это попытка контейнера отправить уведомление на рабочий стол Astra Linux. На создание MP3 не влияет.
  2. Консоль "зависла" без вывода.
    • Статус: Норма. Откройте glances и убедитесь, что процесс piper или ffmpeg загружает ядро CPU.
  3. Нехватка места на диске.
  • Образ audiobook-maker занимает ~1.5 ГБ. Если место критично, после завершения всех дел можно очистить кэш Docker: docker system prune -f (образ придется пересобрать при следующем использовании, но настройки и модели останутся на месте).

Система полностью готова к эксплуатации. Если потребуется настроить пакетную обработку целой папки с книгами (bash-цикл) или изменить скорость речи (pitch/speed rate), дайте знать!
