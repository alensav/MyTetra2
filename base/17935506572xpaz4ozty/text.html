Ошибка unrecognized command line option '-std=c17' означает, что версия GCC в вашей системе Astra Linux (вероятно, 6.x или 7.x) слишком стара для компиляции последней версии f3 из GitHub. Новый код f3 использует стандарт C17, который поддерживается только начиная с GCC 8.

Поскольку вы уже установили все необходимые зависимости (build-essential, libudev-dev, libparted-dev), самое простое решение — не компилировать последнюю версию, а загрузить и установить официальный пакет f3 из репозитория Debian Stretch (версия 6.0). Stretch — это базовая система Astra Linux 2.12, и этот пакет изначально скомпилирован для старой версии GCC, поэтому установка пройдёт гладко без ошибок.

✅ Решение: установка f3 6.0 из репозитория Stretch

В вашем списке источников уже есть archive.debian.org/debian stretch-backports, но основная ветка Stretch, возможно, не включена. Мы можем загрузить пакет напрямую и установить его вручную, что не повлияет на систему.

1. Загрузка пакета
Выполните в терминале следующую команду для загрузки версии f3 6.0 для amd64 (это стабильная версия, проверенная на Debian Stretch):

bash

wget http://archive.debian.org/debian/pool/main/f/f3/f3_6.0-3_amd64.deb

Примечание: если выдаст ошибку сертификата, добавьте параметр --no-check-certificate.

2. Установка

bash

sudo dpkg -i f3_6.0-3_amd64.deb

3. Проверка

bash

f3probe --version

Если отобразится версия, установка успешна. Эта версия 6.0 содержит f3probe и f3write/f3read, чего вполне достаточно для проверки поддельных флешек.

💡 Почему не стоит упорствовать с компиляцией новой версии

В вашей системе libc6 — это 2.24 (Debian 9 Stretch), а GCC также старый. Хотя теоретически можно было бы изменить -std=c17 в Makefile на -std=c11, чтобы попытаться обойти проблему, в новом коде f3 могут использоваться другие языковые возможности, не поддерживаемые старым компилятором, что приведёт к новым ошибкам. Установка старой версии, скомпилированной для Stretch, — это наиболее надёжный и быстрый способ, позволяющий сразу перейти к проверке флешки.

После установки не забудьте сначала выполнить lsblk для определения устройства (например, /dev/sdb), затем использовать sudo f3probe --destructive --time-ops /dev/sdb для быстрой проверки.

alensavas@astra:~/f3$ sudo make install-extrawget http://archive.debian.org/debian/pool/main/f/f3/f3_6.0-3_amd64.deb make: *** Нет правила для сборки цели «install-extrawget». Останов. alensavas@astra:~/f3$

Понял, вы случайно склеили две команды в одну: install-extrawget — это не команда. Терминал попытался выполнить make с такой целью и закономерно выдал ошибку.

Просто выполните команды по очереди. Сначала выйдите из папки f3 (или оставайтесь, это не важно), затем скачайте пакет:

bash

wget http://archive.debian.org/debian/pool/main/f/f3/f3_6.0-3_amd64.deb

Если wget выдаст ошибку сертификата (часто бывает на Astra), используйте:

bash

wget --no-check-certificate http://archive.debian.org/debian/pool/main/f/f3/f3_6.0-3_amd64.deb

После скачивания установите:

bash

sudo dpkg -i f3_6.0-3_amd64.deb

И проверьте:

bash

f3probe --version

Если отобразится версия — всё готово, можно переходить к проверке флешки. Команда make install-extra вам больше не нужна, так как вы ставите готовый пакет, а не компилируете из исходников.

alensavas@astra:~/f3$ f3probe --version F3 Probe 6.0 alensavas@astra:~/f3$

Отлично, установка прошла успешно! Теперь f3probe версии 6.0 готов к работе. Переходим к главному — проверке вашей флешки.

🚀 Пошаговая проверка флешки

1. Вставьте флешку и определите её устройство

bash

lsblk

Найдите в выводе вашу флешку. Обычно это /dev/sdb или /dev/sdc (смотрите по размеру и названию). Важно: используйте имя всего диска (например, /dev/sdb), а не раздела (/dev/sdb1).

2. Размонтируйте флешку (если она автоматически смонтировалась):

bash

sudo umount /dev/sdb*

Замените sdb на ваше устройство.

3. Запустите быстрый тест
⚠️ Внимание: эта команда полностью сотрёт все данные на флешке! Если на ней есть что-то важное, сначала скопируйте.

bash

sudo f3probe --destructive --time-ops /dev/sdb

Замените sdb на ваше устройство.

📊 Как читать результат

  • Если флешка настоящая, вы увидите что-то вроде:

text

Good news: The device is not counterfeit.

и реальный объём совпадёт с заявленным.

Если флешка поддельная (как в вашем случае с AxoFlashTest), вывод будет примерно таким:

text

Bad news: The device is counterfeit.

...

Real size: 7.4 GB (7948206080 bytes)

  • Программа покажет реальный объём чипа — скорее всего, около 7–8 ГБ вместо заявленных 4000 МБ (что странно, но суть та же — объём завышен).

💡 Что делать дальше

Если тест подтвердит подделку:

  1. Не используйте флешку для важных данных — записи за пределами реального объёма будут теряться.
  2. Верните товар продавцу, приложив скриншот вывода f3probe как доказательство.
  3. Если вернуть нельзя, можно «урезать» флешку до реального размера командой f3fix, но это не решит проблему с качеством чипа — он всё равно может быстро выйти из строя.

Запускайте проверку и покажите вывод — помогу интерпретировать результат.
