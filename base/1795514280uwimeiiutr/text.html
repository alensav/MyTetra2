Cтруктурированная инструкция по максимально эффективному использованию этого инструмента.


📌 Шаг 1: Настройка рабочего пространства (My Work)

Главный экран приложения — это дашборд My Work. Здесь отображаются все ваши активные задачи.

  1. Нажмите "Connect Repository" (или "Add local folder").
  2. Выберите ваш репозиторий (например, alensav/MyTetra2 или любую другую вашу разработку).
  3. Приложение автоматически подтянет открытые Issues и Pull Requests из GitHub.


📌 Шаг 2: Запуск агентской сессии

Вместо того чтобы писать код вручную, вы делегируете задачу агенту.

  1. Нажмите "New Session" или выберите конкретный Issue из списка.
  2. Выберите тип песочницы (Sandbox):
    • Local Sandbox: Агент работает прямо в файловой системе вашего контейнера (имеет ограниченный доступ к сети и файлам). Рекомендуется для начала.
    • Cloud Sandbox: Эфемерная Linux-среда на серверах GitHub. Не нагружает ваш ПК, сессия сохраняется, даже если вы закроете приложение.
  3. Выберите режим работы (Session Mode):
  • 🟢 Interactive (Интерактивный): Агент делает один шаг и ждет вашего подтверждения. Используйте для сложных рефакторингов или незнакомых частей кода.
  • 🟡 Plan (Планирование): Агент сначала составляет подробный план действий (список файлов для изменения, логику). Вы проверяете план, одобряете его, и только потом агент начинает писать код. Идеально для новых фич.
  • 🔴 Autopilot (Автопилот): Агент работает от начала до конца без промежуточных вопросов. Используйте только для рутинных, низкорисковых задач (например, обновление зависимостей, написание тестов, исправление опечаток).


📌 Шаг 3: Использование Canvases (Рабочих поверхностей)

Забудьте о бесконечной прокрутке чата. Canvases — это двусторонние рабочие доски.

  • Когда агент работает, он создает Canvas, где в реальном времени отображает:
    • Список задач (TODO list), которые он выполняет.
    • Изменения в коде (diff).
    • Вывод терминала (результаты компиляции или тестов).
  • Ваша роль: Вы можете редактировать этот план, удалять лишние шаги, одобрять конкретные изменения или перенаправлять агента прямо на этой доске.


📌 Шаг 4: Магия Git Worktree (Изоляция)

Вам не нужно вручную создавать ветки (git checkout -b).

  • Для каждой агентской сессии приложение автоматически создает изолированный git worktree.
  • Вы можете запустить 3 разных агента для 3 разных задач в одном репозитории одновременно. Они не будут перезаписывать файлы друг друга, так как работают в своих изолированных копиях рабочей директории.
  • Кнопка "Open in VS Code" (если установлена) откроет именно этот worktree в вашем редакторе для глубокой проверки.


📌 Шаг 5: Agent Merge и завершение работы

Когда агент завершил задачу, он создает Pull Request. Но его работа на этом может не закончиться (функция Agent Merge):

  1. Агент автоматически мониторит GitHub Actions (CI/CD).
  2. Если тесты упали, агент сам анализирует логи ошибок, вносит исправления и пушит новые коммиты.
  3. Если CI прошел успешно и получены необходимые аппрувы (согласно вашим Branch Protection Rules), агент может автоматически выполнить слияние (Merge). Вы контролируете, на каком этапе агент должен остановиться и передать задачу вам.


⚠️ Важные советы для вашего workflow (Astra Linux + Docker)

  1. Мониторинг ресурсов: Поскольку каждый локальный worktree и агент потребляют оперативную память и CPU, держите открытым htop или glances (которые вы уже используете), чтобы следить за нагрузкой на систему при запуске нескольких агентов одновременно.
  2. Экономия AI-кредитов: Режимы Autopilot и использование больших контекстных окон (1M токенов) быстро расходуют лимиты. Начинайте с режима Plan, чтобы убедиться, что агент понял задачу правильно, прежде чем давать ему "карт-бланш".
  3. Очистка: Если вы работаете в Local Sandbox, приложение обычно само очищает worktree после мержа или закрытия сессии. Но периодически проверяйте дисковое пространство.
  4. Запуск: Не забывайте, что для запуска приложения вы всегда используете ваш скрипт:

🚀 Практическое задание для первого запуска

Чтобы обкатать систему без риска для основных проектов:

  1. Создайте тестовый репозиторий на GitHub (например, test-copilot-app).
  2. Клонируйте его и подключите к Copilot App.
  3. Создайте Issue с текстом: "Создай простое Python-приложение (скрипт), которое выводит текущую температуру CPU (используя заглушку или библиотеку psutil), и напиши для него unit-тест".
  4. Запустите сессию из этого Issue в режиме Plan.
  5. Оцените предложенный план, одобrite его и посмотрите, как агент создаст файлы, запустит тесты в своем Canvas и предложит Pull Request.

Если на каком-то этапе интерфейс покажется непонятным или возникнет ошибка (особенно связанная с правами доступа внутри контейнера) — пишите, разберем конкретный шаг!
