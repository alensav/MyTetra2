Часть I. Базовое руководство

1. Архитектура — как всё связано

Покупатель → Сайт proekts → orders (pending) → ЮKassa → оплата
ЮKassa → webhook → yookassa-webhook.php → orders.status=paid
Docker yookassa-to-mynalog (каждые 5 мин) → ФНС «Мой налог» → чек → SQLite
downloads → токены → download.php → файл покупателю

Важно: Docker не слушает webhook — опрашивает ЮKassa каждые 5 минут. Webhook нужен, чтобы сайт быстрее узнал об оплате.

4. Наладка — типовые операции

4.1. Заказ оплачен, но статус не paid

sudo mysql proekts -e "UPDATE orders SET status='paid', paid_at=NOW(), payment_id='<UUID>' WHERE order_number='ORD-XXXX';"

4.2. Заказ paid, но нет токенов на скачивание

sudo mysql proekts -e "INSERT INTO downloads (order_id, token, downloads_left, created_at) VALUES (<ID>, SHA2(CONCAT(<ID>, NOW(), RAND()), 256), 3, NOW());"

4.3. Покупатель не может скачать файл

sudo mysql proekts -e "SELECT * FROM downloads WHERE token='<TOKEN>';"
ls -la /path/to/files/<filename>

sudo docker compose -f /opt/yookassa-to-mynalog/docker-compose.yml exec yookassa-to-mynalog tail -30 /app/logs/sync.log

6. Использование магазина — сценарий покупателя

  1. Покупатель заходит на сайт → выбирает товар → оформляет заказ.
  2. Сайт создаёт orders (status=pending) и отправляет в ЮKassa.
  3. Покупатель платит на стороне ЮKassa.
  4. ЮKassa шлёт webhook → yookassa-webhook.php → orders.status=paid.
  5. Покупатель видит «🎉 Платёж прошёл!» и кнопку [Получить].
  6. Docker (в течение 5 минут) создаёт чек в «Мой налог».
  7. Покупатель скачивает файл по ссылке download.php?token=....
  8. downloads_left уменьшается на 1.

⬆️ В начало | ⬅️ Назад: Диагностика | ➡️ Вперёд: Использование архива

7. Использование архива — что это и где

  • MySQL proekts — заказы, платежи, токены, пользователи.
  • SQLite внутри контейнера — платежи, чеки, sync_state, refunds.
  • Файлы товаров — на диске VPS (путь уточнить в download.php).
  • Логи — sync.log, webhook-лог, nginx/apache access.log.

Резервное копирование:

#!/bin/bash
# /root/backup/backup_proekts.sh
set -e
DATE=$(date +%F_%H-%M)
BACKUP_DIR=/root/backup
mkdir -p "$BACKUP_DIR"
mysqldump proekts | gzip > "$BACKUP_DIR/proekts_$DATE.sql.gz"
sudo docker compose -f /opt/yookassa-to-mynalog/docker-compose.yml exec -T yookassa-to-mynalog tar czf - /app/data > "$BACKUP_DIR/container_data_$DATE.tgz"
cp /opt/yookassa-to-mynalog/.env "$BACKUP_DIR/env_$DATE.txt"
find "$BACKUP_DIR" -type f -mtime +30 -delete
echo "Backup done: $DATE"

9. Мониторинг — что стоит настроить

#!/bin/bash
# /root/scripts/check_health.sh
STATUS=$(sudo docker inspect --format='{{.State.Health.Status}}' yookassa-to-mynalog)
PENDING=$(sudo docker compose -f /opt/yookassa-to-mynalog/docker-compose.yml exec -T yookassa-to-mynalog tail -100 /app/logs/sync.log | grep -c "осталось=1")
if [ "$STATUS" != "healthy" ] || [ "$PENDING" -gt 0 ]; then
  echo "⚠ yookassa-to-mynalog: status=$STATUS, pending=$PENDING" | mail -s "ALERT proekts" admin@example.com
fi

Cron: 0 * * * * root /root/scripts/check_health.sh

10. Регламент действий при инциденте

  1. Зафиксировать: время, симптом, что видит покупатель.
  2. docker compose ps — контейнер жив?
  3. tail -50 /app/logs/sync.log — что в логе?
  4. docker inspect Health — degraded/pending?
  5. По таблице раздела 5 — определить причину.
  6. Применить решение из раздела 4.
  7. Если чек не создался за 2 часа — проверить curl до API ФНС.
  8. Если ФНС недоступен >24 ч — создать чек вручную в приложении «Мой налог».
  9. Записать инцидент в журнал (дата, причина, решение).
