🌐 Скриншот 3 — встроенный Browser и ошибка Yandex

Это не баг ArozOS. Встроенный «Browser» — это просто <iframe>-обёртка. А yandex.ru (и dzen.ru) отдают заголовок X-Frame-Options: DENY / CSP frame-ancestors, чтобы запретить встраивание (защита от clickjacking). Поэтому Firefox честно отказывает.

👉 Решение: в адресной строке встроенного браузера есть иконка «открыть в новом окне» (квадрат со стрелкой) — она выбросит страницу во внешнюю вкладку, где iframe-ограничение не действует. В целом этот модуль годится для сайтов без защиты от фреймов (ваш собственный статический сайт, внутренние сервисы), но не как универсальный браузер. Это ожидаемое компромиссное поведение web-OS.

📊 Скриншот 4 — панель быстрого доступа (Quick Access)

Здесь два важных наблюдения:

  1. eth0 → 172.17.0.3 — это IP контейнера в bridge-сети Docker. Отличное подтверждение изоляции: ArozOS живёт в своём сетевом пространстве, а не в вашей основной сети Astra.
  2. Диски /dev/sdb (2.7 TB) и /dev/sdc (931.5 GB) с NaN% — контейнер видит метаданные физических дисков хоста (через /sys/block и /proc/partitions, которые Docker по умолчанию не полностью скрывает), но реального доступа к их содержимому у него нет — отсюда NaN% (statfs не работает для не смонтированных в контейнер разделов). Данные хоста недоступны, кроме той папки, которую вы явно примонтировали (/srv/data50gb/arozos-test). Это нормально и безопасно.

⚠️ Скриншот 5 — Power Off / Restart: НЕ НАЖИМАЙТЕ

Предупреждение на экране («Restart / Shutdown is risky… ArozOS will pass the shutdown sequence to the host») написано для bare-metal/VM-установок. В Docker-контейнере поведение непредсказуемо и зависит от привилегий: в худшем сценарии это может повлиять на хост, в лучшем — просто убьёт PID 1 и остановит контейнер.

👉 Управляйте жизненным циклом только через Docker (вы это и так умеете через systemctl/docker):

bash

docker stop arozos-test # «выключить»

docker start arozos-test # «включить»

docker restart arozos-test # «перезагрузить»

Кнопки Power/Restart в интерфейсе для вашей конфигурации — ловушка, игнорируйте их.


🔧 Куда двигаться дальше (связка с вашим стеком)

1. Подключить Mail.ru Cloud как хранилище. ArozOS умеет монтировать удалённые ФС (WebDAV/SMB/SFTP) прямо в Storage Pools. Вы уже монтируете Mail.ru через davfs2 — в ArozOS можно указать тот же WebDAV-URL (https://webdav.mail.ru/...) в System Settings → Disk & Storage → Storage Pools, и облако станет видно в File Manager как отдельный диск. Плюс: свой web-доступ к облаку; минус: дублирование с davfs2 на хосте (учитывайте ваш принцип «нет --delete, чтобы не потерять данные» — в ArozOS используйте режим Read Only для облака).

2. Добавить ffmpeg (сейчас в логах было ffmpeg not installed — из-за этого не работают FFmpeg Factory и перекодирование в Cine Studio). Пересоздайте контейнер, добавив ffmpeg в установку:

bash

1docker rm -f arozos-test

docker run -d --name arozos-test --restart unless-stopped \

-p 8080:8080 \

-v /srv/data50gb/arozos-test:/arozos/files \

debian:bookworm \

bash -c "apt-get update && apt-get install -y wget ca-certificates ffmpeg && \

mkdir -p /opt/arozos && cd /opt/arozos && \

wget https://github.com/tobychui/arozos/releases/latest/download/arozos_linux_amd64 -O arozos_bin && \

wget https://github.com/tobychui/arozos/releases/latest/download/web.tar.gz && \

chmod +x arozos_bin && tar -xzf web.tar.gz && \

./arozos_bin -port 8080 -root /arozos/files"


3. Пробросить папку MyTetra для чтения. Если хотите смотреть свои заметки через File Manager/Terminal, добавьте ещё один volume, например -v /home/alensav/MyTetra_Data:/arozos/mytetra:ro (режим :ro — только чтение, чтобы не сломать вашу синхронизацию с Android/Syncthing).
